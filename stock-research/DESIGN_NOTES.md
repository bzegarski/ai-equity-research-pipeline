# stock-research — design notes

This file is loaded only when iterating on the stock-research skill. The everyday operational rules live in `CLAUDE.md`.

Holds the deliberate tradeoffs (chose them on purpose, document so a future iteration knows why) and decisions deferred until evidence supports.

---

## By-design tradeoffs

These aren't problems — they're choices made with reasoning. If priorities change, revisit:

- **9-10 manual terminal switches per ticker.** High friction. Justified by user's stated priority: output quality over convenience. If you ever want screen automation, this design fails — refactor toward a single-model fallback path with verification done by Claude subagents.
- **No per-stage analytical gates** (Codex doesn't audit business model / industry / moat / accounting / management individually). Codex's proposal for 8 such gates was rejected because PANW data showed 0 corrections at those phases — empirical evidence didn't support the cost. If a future run shows analytical errors surviving Verification C, re-evaluate.
- **`__/5` scorecard tension with the rest of the skill's epistemic discipline.** The memo's Section 2 asks for numerical 1-5 scores. The rest of the skill insists on labeled uncertainty. This tension is acceptable because the scorecard provides a 5-second summary function. If you find the scores feel arbitrary across runs, replace with qualitative labels (Low / Medium / High / Strong).
- **DCF defaults superseded by Round 3.** Pre-Round-3: 10% discount, 3% terminal, 5-year Stage 1 hardcoded in `agents/valuation.md`. Post-Round-3: per-company via `references/discount_rate_logic.md` (long-bond + ERP; 10% floor) and `references/moat_durability_tiers.md` (Stage-1 length 5–15y by moat tier).
- **Codex's MISSION FRAME differs slightly from CC's.** When updating the Codex skill, Codex chose to keep its own writing standards rather than import CC's verbatim. Acceptable inter-model independence; not a bug. The cross-checks reveal any meaningful framing divergence.
- **`customer_perspective_codex_xcheck.md` is asymmetric.** Codex's Step 1D produces this file but CC has no `customer_perspective_cc.md` at that stage (CC's Agent F runs later, in Phase 3). Codex handles this with "if present" logic; the xcheck file mostly says "no CC counterpart at this stage; reconciliation deferred to Phase 3." Functionally fine, slightly wasted file.
- **Codex doesn't summarize 8-K material events.** By design — Codex's Step 1A scope deliberately excludes 8-Ks, even though it reads `recent_8k.txt` in the audit step. CC's Phase 2 Gate and Agent E read 8-Ks directly, so the signal isn't lost. Separate from the 10-K decision (10-K is dual-summary; 8-K is CC-only). If material-event analysis ever feels thin, consider adding 8-K summarization to Codex Step 1A.
- **Codex skill activation uses `$`, not `/`.** The Codex CLI uses `$stock-research-codex` to launch the skill. CC's handoff messages say so explicitly. The MSFT "Codex Unavailable" phantom warning was caused by this confusion alone, not an architectural fragility. Document any future model-CLI prefix changes here.
- **Hard primary-source rule for customer perspective — superseded by axis-based classifier (v1.2).** PAYX's Comparisun-aggregator G2 number propagated to canonical despite Medium-confidence flagging. Soft tagging proved insufficient → hard binary block added. DECK then showed the binary rule over-corrects: APMA HOKA listings (a podiatric medical association — authoritative non-aggregator) were blocked alongside legitimate aggregator noise. v1.2 replaces with a four-axis classifier in Codex SKILL.md (Authority of issuer / Primary vs derivative / Access status / Specificity of claim) plus 6-8 worked examples (APMA Seal pages → ALLOWED; G2 vendor scorecard → BLOCKED; Forrester summary republished by Reuters → BLOCKED unless 3+ outlets; NICE TA875 patient page → ALLOWED). Pattern-match by axis, not by hardcoded list.
- **FPI track (v1.2).** Foreign private issuers file 20-F + 6-K instead of 10-K / 10-Q / 8-K. Phase 0 detects FPI from `submissions.json`, writes `raw/filing_track.yml`, and substitutes filing types per the FPI map in `phases/phase0_download.md`. Refusal only when CORE evidence missing (annual filing OR most-recent interim filing); absence of proxy / Form-4 substitutes is acceptable (`FPI_NO_PROXY`, `FPI_NO_FORM_4` markers, Phase 8 reads as documented limitation). XBRL auto-detects taxonomy (us-gaap → `extract_xbrl.py`; ifrs-full → `extract_ifrs_xbrl.py`). NVO's d2 annual-report exhibit doesn't use 20-F Item numbering, so the section-extraction part of FPI track is untested for that specific filer pattern; raw canonical text is still produced.
- **Phase 3+ agent watchdog (v1.2).** Soft + hard timeout per phase (Phase 3 / 4 / 6: 8m soft, 25m hard; Phase 5: 12m soft, 25m hard) plus missing/zero-byte output check. Retries once with logged trigger reason in `bugs_encountered.md`. Formalizes the manual Phase 4 retry pattern that already worked on NVO and would have caught Phase 5's 6h 37m runaway.
- **Deep Research is opt-in, model-split.** `$stock-research-codex TICKER --deep-customer` (uses `o4-mini-deep-research`) for messy product/customer markets where review evidence is fragmented. `$stock-research-codex TICKER --deep-attack-research` (uses `o3-deep-research`) for adversarial base rates and historical analogs in Phase 6. Default-off — deep research adds time and probabilistic layer; use only when filings can't answer the outside-source question.
- **Drop competitors from Codex Phase 0 audit (do not produce `competitors_codex.md`).** PAYX/MSFT evidence: the catches that mattered came from proxy / 10-Q / transcript / customer perspective / consistency. Adding a Codex competitor pass would produce redundant broad peer summaries without high-yield catches. Phase 0 audit narrows competitor handling to "file exists and is nonempty."
- **Adoption-status reporter (CC side).** When Codex flags a CC error in `*_codex_xcheck.md`, CC must visibly adopt or reject in `cc_catches_against_codex.md` Section 1. Closes the integration loop.

## Deferred decisions (intentionally pending evidence)

These were considered and intentionally not implemented yet — implement only after evidence supports:

- **Asymmetric model specialization (Slice 5).** PANW evidence suggested CC stronger on proxy compensation depth and Codex stronger on 10-Q Item 5 / segment-level proxy data. With n=6 (PANW + PAYX + MSFT + DECK + SNOW + NVO) the gate is met but no specialty clustering emerged — catches in NVO/SNOW/DECK are distributed across both sides. **Not supported at n=6; revisit only if a stronger pattern emerges at n=8+** (especially with industries we haven't yet covered: banks, mining, REITs, regulated utilities). Keep open at higher empirical bar rather than retire.
- **Multi-quarter transcript "absence-tracking".** Linguistic-change tracking ("topics raised in 2022 that went quiet in 2024") is high-value but failure surface is wide — needs ≥2 verbatim transcripts, which isn't reliable. Implement only after transcript-source-quality data shows ≥2 verbatim quarters consistently across runs.
- **A2-style "5-10 historical analogs from training data" in Phase 6 base rate.** Replaced with external-distribution anchoring (Damodaran, French, sector tables). Don't revert to LLM-generated reference-class lists.
- **Q1 word-count symmetry enforcement** between bull and bear cases. Goodhart's law: agent learns to pad bear case rather than think harder. The memo prompt instead asks for "substantive parity" qualitatively. If bear cases consistently feel thin in actual runs, add a verification pass that checks claim-by-claim parity, not word count.
- **Dual-model architecture for Phase 6 counter-attack.** Currently Codex `--attack` is optional; consider making it standard if Phase 6 confabulation rates are high enough.
- **Verification D never-fired observation** — add a deliberately-confabulated Key Insight test ticker to confirm D actually rejects.
- **Quarterly review process for `outcomes_log.md`** — append-only log exists; the review cadence isn't yet formalized.
